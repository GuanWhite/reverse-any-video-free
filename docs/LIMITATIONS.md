# 功能边界与已知限制

## 1. 功能边界：与上游逐项对照

| 能力 | 上游 `reverse-any-video`（Pro） | 本 skill（free） | 判定 |
| --- | --- | --- | --- |
| 画布 / 分数帧率 / 帧数时长测量 | `reverse start` probe | `probe.py` | **保留**，且字段更多 |
| 精确切点（含一镜内跳切、推近） | `measure cuts` | `cuts.py` 逐帧 MAD + 自适应基线，推近/溶解另列低置信提示 | **保留**，提示类需人工确认 |
| 连续帧阅读、ROI 裁切 | `measure frames` | `frames.py` + manifest + contact sheet | **保留** |
| 字幕切换帧（像素口径） | `measure events --roi` | `cuts.py --roi` | **保留** |
| 文字/字幕/UI/图表用 HTML 重建 | 是 | 是 | **保留** |
| 照片/Logo/贴图按框裁切 | 是 | 是（Logo 不依赖在线目录） | **保留** |
| 绘制匹配方法与 CSS/SVG 配方 | `match.md` | `references/rebuild.md` 完整收录 | **保留** |
| 原音轨整条直挂、片段静音 | 是 | 是 | **保留** |
| 可编辑 HTML 时间轴工程 | 是 | 是（契约内嵌，不依赖上游 skill） | **保留** |
| 结构检查 / 本地渲染 / 预览 | 是（开源免费部分） | 是，全部**可选** | **保留** |
| 逐帧 diff：漏切/多切、时长、最差帧并排图 | `hyperframes diff` | `diff.py` + ffmpeg PSNR/SSIM + 并排图 | **保留** |
| 音画偏移 | diff 报出精确偏移 | 100 Hz 包络互相关，**10 ms 分辨率估计** | **降级** |
| 内容缺失区间 | diff 报出 | 连续低 PSNR 段 | **保留（启发式）** |
| 出镜人物重拍（换脸、去烧录字） | HeyGen 生成，Pro + credits | 按人物框裁切原片并静音 | **不提供** |
| 人脸框自动对齐（≤5%） | `measure face` | 无 | **不提供** |
| 动画/手绘/3D 整镜生成与 retime | 生成式，Pro + credits | 整镜裁切 + 能代码化的层重建 | **不提供生成** |
| 云端渲染 | `cloud render`（按 credit 计费） | 本地渲染 | **不提供（也不需要）** |
| 计划/额度/登录/升级交互 | `start.md` 全篇 | 全部移除 | **不提供** |
| 遥测上报 | `events` | 无 | **不提供** |

## 2. 因移除 Pro 而必然存在的能力损失

1. **人脸不会被替换**：原片人物的脸、衣服、背景会原样保留在裁切片段里；原片烧录在人物区域内的字幕也会一起带过来。上游重拍的目的正是让"原片的脸和烧录字不进入成品"，这一点免费版做不到。
2. **没有生成式画面**：动画角色表演、形变、流线细节等"代码画不出正确形状"的部分只能是原片整镜，标注为不可编辑片段。上游本也承认生成结果只是"可替换的 clip，不是可改的层"，但至少画面与原片解耦。
3. **没有自动人脸框对齐**：镜头起止的人脸位置需要人工用 `frames.py` 读帧比对。
4. **没有登录目录的 Logo/素材检索**：Logo 只能从原帧裁切或由使用者提供原始素材。

## 3. 算法与工程限制

| 限制 | 表现 | 建议 |
| --- | --- | --- |
| 切点检测是启发式 | 强颗粒、强压缩噪声、闪光灯、快速甩镜可能多报；极轻微跳切可能漏报 | 导出 `--score-curve`，用 `--threshold` / `--min-abs` 调参，并用连续帧复核；`reframe_hints` 一律人工确认 |
| 只处理 CFR | VFR 源的时间换算可能错位 | 先用 ffmpeg 转 CFR 再测 |
| 逐帧 MAD 缩到 160×90 | 极小区域的变化（几像素的图标）可能不明显 | 对该区域用 `--roi` 单独测 |
| PSNR / SSIM 是像素指标 | 颗粒、胶片感、替换字体、压缩噪声都会显著拉低分数 | 匹配观感，不追像素分数；上游也明确 "Grain lowers SSIM whatever you do" |
| 音画偏移是估计 | 10 ms 分辨率、基于响度包络；静音片或纯音乐片可能返回 `null` | 用 `--no-audio-offset` 跳过或在报告中标注不可判读 |
| 并排图 / contact sheet 需 Pillow | 缺失时只有独立 PNG | 报告中会写明 `exporter` 与缺失项 |
| 单次连续帧上限 600 帧 | 更长区间被拒绝 | 长片分段，`--range` 多次调用 |
| `diff.py` 假设同尺寸同帧率 | 不一致时 PSNR/SSIM 可能为空 | 先按 `probe.json` 对齐再比 |
| 渲染器不在本项目内 | 不装 HyperFrames CLI 时需自行接免费 HTML→视频渲染器 | 见 `references/composition.md` B 路径 |
| 无自动字体匹配 | 替换字体宽度不同 | 按墨迹框量，且把替换记入 `REVERSE_FREE.md` |
| 长片与高分辨率耗时 | 全片逐帧解码是 O(帧数) | 分段处理；`--range` 限制范围；脚本流式读取，内存占用恒定 |

## 4. 不适用场景

- 需要"换掉画面里的人 / 去掉原片烧录字 / 生成原片没有的画面"——这些必须走生成式能力，本 skill 明确不做。
- 需要逐帧像素级 100% 一致——目标应是"可编辑工程 + 视觉对齐"，不是复制一份 mp4。
- 需要在线素材库、云端渲染、团队协作或账号体系——本 skill 是纯本地离线工具。
- 没有合法授权的视频——SKILL.md 明确保留上游的合规条款："只复刻使用者有权使用的视频"。涉及真人肖像、第三方 Logo、音乐、字体时，授权由使用者负责。

## 5. 与"高还原度"的诚实关系

本 skill 保留了决定还原度的**方法论**（帧级测量、分层重建、匹配配方、量化验收闭环），但把这四件事从商业 CLI 的自动化里搬到了本地脚本 + Agent 的判断上。因此：

- 对**动效图文、字幕卡、数据动画**类视频，仍可接近上游的逐帧对齐效果；
- 对**口播、实拍、动画**类视频，因不做生成式重拍，成品更接近"结构化剪辑 + 可编辑叠层"，与原片的画面耦合度更高；
- 最终相似度很大程度取决于 Agent 是否真的按 `measurement.md` 读连续帧、按 `rebuild.md` 量墨迹框，而不是只看脚本输出的分数。

上游宣称的 "matches the original frame for frame" 是**目标与验收口径**，不是保证；本 skill 同样不作此保证。
